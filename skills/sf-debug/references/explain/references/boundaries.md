# Boundaries

Read with `sf-debug mode:explain/SKILL.md`. Procedure lives here.

## Boundaries
- **Not a verdict.** `sf-debug mode:explain` teaches what X is and how it works. For Salesforce product, adoption, delivery, or org-health judgment, use `sf-product-pulse` when its role-aware pulse fits; otherwise answer the decision request directly.
- **Not repo memory.** Documenting a solved problem for future work is `sf-compound`. sf-debug mode:explain teaches the human, not the repo.
- **Not ideation or scoping.** An idea input is explained as given — implications and trade-offs — never expanded into options or a requirements dialogue.
- **The check-in is static.** It is a section of the explainer. The run does not quiz the user or wait for answers. Writing the answers into that section is the product; a blocked chat quiz is not.
