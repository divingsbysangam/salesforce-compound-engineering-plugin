# Boundaries

Read with `sf-explain/SKILL.md`. Procedure lives here.

## Boundaries
- **Not a verdict.** `sf-explain` teaches what X is and how it works. For Salesforce product, adoption, delivery, or org-health judgment, use `sf-product-pulse` when its role-aware pulse fits; otherwise answer the decision request directly.
- **Not repo memory.** Documenting a solved problem for future work is `sf-compound`. sf-explain teaches the human, not the repo.
- **Not ideation or scoping.** An idea input is explained as given — implications and trade-offs — never expanded into options or a requirements dialogue.
- **The check-in is never headless.** It exists to exercise the human; automating the answers deletes the product.
