# /flow-generate

> **Principles enforced:** 1 (preserve the quality ceiling), 4 (spec is the artifact), 2 (verifiability). See `PRINCIPLES.md`.

## Copy-paste-to-agent

```
Generate a Salesforce Flow by running the strict 3-step MCP pipeline. The pipeline IS the
contract: fetchGroundedObjectMetadata → flowElementSelection → flowElementGeneration.
Loop on flowElementGeneration with the same operationId until isComplete=true. Never
hand-write Flow XML. Never skip steps. After XML is returned, validate with
sf code-analyzer and dispatch flow-governor-monitor + flow-complexity-analyzer review
agents in parallel. Bulkify per Salesforce flow best practices: no DML/SOQL inside loops.
```

## When to use

Use for any Flow type:

* **Screen Flow** — user-guided, multi-step data collection

* **Autolaunched Flow** — background processing, called from Apex / Process / button

* **Record-Triggered Flow (before-save)** — same-record field updates, validation

* **Record-Triggered Flow (after-save)** — related-record DML, async actions

* **Scheduled Flow** — recurring or time-based batch automation

If the request is ambiguous between a Flow and an Apex trigger, route via `/sf-brainstorm` first — the declarative-vs-code matrix lives there.

***

## The pipeline is non-negotiable

Flow XML is generated by running the **`execute_metadata_action`** MCP tool with three sequential `action` values. **Never hand-write Flow XML.** Hand-written Flow XML fails deployment in subtle ways (missing region IDs, wrong reference syntax, broken element ordering).

### Step 1 — `fetchGroundedObjectMetadata`

| Input              | Type              | Notes                                                                                                                                                                              |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `userPrompt`       | string (required) | The user's natural-language request                                                                                                                                                |
| `inflightMetadata` | array (required)  | Custom objects/fields from the local sfdx project. Use `[]` if none. |

Output: `groundingMetadata` (string — already serialized; pass directly to Step 2).

### Step 2 — `flowElementSelection`

| Input               | Type              | Notes                                                                                                                                                           |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `userPrompt`        | string (required) | Same value as Step 1                                                                                                                                            |
| `groundingMetadata` | string (required) | Pass-through from Step 1; do **not** re-serialize |
| `operationId`       | string (required) | Empty string `""` for the first call              |

Output: `operationId` (carry to Step 3) + `userOutput` (reasoning to surface to the user).

### Step 3 — `flowElementGeneration` (loop until complete)

| Input           | Type              | Notes                                                                         |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| `operationId`   | string (required) | From Step 2 output                                                            |
| `requestSource` | string (required) | `"A4V"` for XML output |

Output: `isComplete` (boolean) + `result` (string — final XML when `isComplete=true`).

**Loop discipline:**

* A flow can have any number of elements (10–50+). Each call generates one element.

* Call `flowElementGeneration` repeatedly with the **same** `operationId`.

* Do **not** pause, summarize mid-loop, or ask the user to confirm continuation.

* Stop only when `isComplete=true` **or** the call returns errors. There is no max iteration count.

* When `isComplete=true`, extract the XML from `result`.

* Task `sf-repo-research-analyst(flow_intent)` — what flows / process builders / Apex automations already touch this object?

* Read `skills/governor-limits/SKILL.md` for flow-specific limits.

## Post-generation validation (mandatory, Principle 2)

Once the pipeline returns XML, do **not** declare success without these checks:

1. **Persist the metadata.** Save under `force-app/main/default/flows/<FlowApiName>.flow-meta.xml`.
2. **Static analysis.** Run `sf code-analyzer run --target <path> --json` and remediate sev0/sev1/sev2.
3. **Parallel review agents** (Principle 1):

   * Task `flow-governor-monitor(flow_xml)` — verifies no DML/SOQL in loops, fault paths present

   * Task `flow-complexity-analyzer(flow_xml)` — flags excessive branching, unbounded loops

   * Task `process-automation-strategist(flow_xml)` — confirms Flow vs Apex was the right call
4. **Bulk-safe entry.** For record-triggered flows, confirm entry conditions filter early to avoid wasted invocations across 200-record bulk imports.
5. **Fault handling.** Every flow with DML or callouts must have a fault path that captures and surfaces errors (Principle 1 — failures cannot be silent).

***

## Hard constraints (every rule fails the deliverable if violated)

| Rule                                       | Why                                                                                                                                                                                     |
| ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Never hand-write Flow XML                  | Pipeline correctness is in the tool, not the LLM                                                                                                                                        |
| Bulkify — no DML/SOQL inside Loop elements | Governor limits multiply per record                                                                                                                                                     |
| Entry conditions on record-triggered flows | Skip records that don't need the flow; scale safety                                                                                                                                     |
| Fault path on every DML / callout          | Errors must surface, never silently swallow                                                                                                                                             |
| Element naming follows project convention  | E.g., `Get_<Object>_Details`, `Decision_Check_<Field>`                    |
| API name follows project convention        | `<Object>_<Trigger>_<Action>` (e.g., `Lead_BeforeSave_PopulateTerritory`) |
