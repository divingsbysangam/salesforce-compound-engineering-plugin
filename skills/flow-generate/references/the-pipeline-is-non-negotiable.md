# The pipeline is non-negotiable

Read with `flow-generate/SKILL.md`. Procedure lives here.

## The pipeline is non-negotiable
Flow XML is generated by running the **`execute_metadata_action`** MCP tool with three sequential `action` values. **Never hand-write Flow XML.** Hand-written Flow XML fails deployment in subtle ways (missing region IDs, wrong reference syntax, broken element ordering).

### Step 1 — `fetchGroundedObjectMetadata`

| Input              | Type              | Notes                                                                                                                                                                              |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `userPrompt`       | string (required) | The user's natural-language request                                                                                                                                                |
| `inflightMetadata` | array (required)  | Custom objects/fields from the local sfdx project. Use `[]` if none. |

Output: `groundingMetadata` (string — already serialized; pass directly to Step 2).

### Step 2 — `flowElementSelection`

| Input               | Type              | Notes                                                                                                                                                           |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `userPrompt`        | string (required) | Same value as Step 1                                                                                                                                            |
| `groundingMetadata` | string (required) | Pass-through from Step 1; do **not** re-serialize |
| `operationId`       | string (required) | Empty string `""` for the first call              |

Output: `operationId` (carry to Step 3) + `userOutput` (reasoning to surface to the user).

### Step 3 — `flowElementGeneration` (loop until complete)

| Input           | Type              | Notes                                                                         |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| `operationId`   | string (required) | From Step 2 output                                                            |
| `requestSource` | string (required) | `"A4V"` for XML output |

Output: `isComplete` (boolean) + `result` (string — final XML when `isComplete=true`).

**Loop discipline:**

* A flow can have any number of elements (10–50+). Each call generates one element.

* Call `flowElementGeneration` repeatedly with the **same** `operationId`.

* Do **not** pause, summarize mid-loop, or ask the user to confirm continuation.

* Stop only when `isComplete=true` **or** the call returns errors. There is no max iteration count.

* When `isComplete=true`, extract the XML from `result`.
